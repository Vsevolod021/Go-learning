# Шпаргалка: этап 1 + интерфейсы

## Главное правило Go

**Копируется содержимое переменной, ровно оно и ничего больше.** Всё поведение
при присваивании и передаче в функцию следует из того, что лежит в переменной.

| тип | что в переменной | копия |
|---|---|---|
| `int`, `string`, `bool` | значение | независимая |
| `struct` без указателей, массив | все поля / элементы | независимая |
| `*T` | адрес | общий объект |
| `[]T` слайс | `ptr`, `len`, `cap` | данные общие, `len` свой |
| `map[K]V` | `ptr` | всё общее (как `obj1 = obj2` в JS) |
| интерфейс | (тип, значение) | копия того, что внутри |

Копия всегда поверхностная. Глубокой она выглядит, только когда вглубь копировать нечего.

## Базовые ловушки

- `:=` только внутри функций; на уровне пакета — `var`.
- Неиспользуемая переменная или импорт — ошибка компиляции.
- `int(2.9)` → `2`, `int(-2.9)` → `-2`: отбрасывает дробь, как `Math.trunc`.
- `len("Привет")` → 12: строки в UTF-8, `len` считает байты. Символы — `range` или `utf8.RuneCountInString`.
- `rune` = `int32`. `string(65)` → `"A"`, а не `"65"`. Число в текст: `strconv.Itoa`, `fmt.Sprintf("%d")`.
- `5` — нетипизированная константа: `Age(20) + 5` работает, `Age(20) + n` (где `n int`) — нет.
- `type Age int` — новый тип (можно методы). `type Age = int` — просто псевдоним.

## Указатели

```go
p := &x     // взять адрес
*p = 20     // записать по адресу
u.Age       // для *User: сахар вместо (*u).Age
*u.Age      // ошибка: точка сильнее звёздочки → *(u.Age)
```

- Zero value указателя — `nil`. Разыменование `nil` — паника.
- `nil` = «значения нет»: поиск не нашёл, поле не передали (`Age *int` ≈ `age?: number`).
- `int`, `string`, `struct` не бывают `nil` вообще.
- `&User{...}` — основной способ получить указатель на структуру. `new(T)` редок.

## Слайсы

```go
s = append(s, x)         // результат ОБЯЗАТЕЛЬНО присваивать
b := slices.Clone(a)     // независимая копия
f := e[0:2:2]            // срез с cap = 2: append не испортит e
var s []int              // идиоматичный пустой слайс, append работает
```

- `cap` — размер выделенного массива. При нехватке `append` выделяет новый и копирует.
- `append` разделяет слайсы, **только** если `len == cap`. Предсказать нельзя — не полагайся.
- `e[0:2]` наследует `cap` до конца массива: `append` молча перезапишет `e[2]`.
- `copy(dst, src)` копирует `min(len(dst), len(src))`. В `var dst []int` скопирует 0.
- В функции `s[0] = 0` видно снаружи, `append` — нет. Возвращай слайс, а не бери `*[]T`.

## Мапы

```go
m := make(map[string]int)          // или литерал; var m map[...] — только для чтения
if v, ok := m[k]; ok { ... }       // есть ли ключ
```

- Чтение отсутствующего ключа — zero value, не паника.
- Запись в `nil`-мапу — паника.
- Порядок `range` намеренно случайный. Нужен порядок — собери ключи и `slices.Sort`.
- Сравнение — `maps.Equal`, копия — `maps.Clone`. `==` только с `nil`.
- Элемент мапы не адресуем: для мутации методами храни `map[K]*T`.

## Методы и получатели

Два правила, из которых следует всё:

1. **Pointer receiver нужен адрес.** Есть адрес — работает. Нет — не работает.
2. **Value receiver нужна копия.** Из указателя Go сделает копию. Из `nil` — паника.

| тип | method set |
|---|---|
| `T` | методы на `T` |
| `*T` | методы на `T` и на `*T` |

- **Сахар вызова** (`u.M()` → `(&u).M()`) работает на переменных с адресом.
- **Method set** решает, подходит ли тип под интерфейс. Сахара там нет.
- Нет адреса: литерал, результат функции, элемент мапы, значение в интерфейсе.
  Исключение: `&T{...}` можно.
- Методы объявляются только в пакете типа.

**На практике:** у структур все методы на `*T`, передаёшь `&v`. `String()` и `Error()` — на `T`.

## Интерфейсы

```go
type Greeter interface { Greet() string }   // только методы, без полей

var _ Greeter = (*User)(nil)                // проверка соответствия при компиляции

v := g.(*User)                              // паника, если там не *User
v, ok := g.(*User)                          // без паники

switch v := g.(type) {                      // type switch
case *User:   // v — *User
case Bot:     // v — Bot
default:      // v — Greeter (то же в case A, B:)
}
```

- `implements` нет. Соответствие проверяется **в месте использования**, сигнатура — точь-в-точь.
- Интерфейс объявляют у потребителя, маленьким.
- Через интерфейс доступны только его методы.
- `%T` печатает конкретный тип, а не интерфейс.
- В type switch срабатывает первый подходящий `case`: конкретные типы — выше интерфейсов.
- `any` = `interface{}`. Подходит всё, но ничего нельзя без проверки — это `unknown` из TS.
- **nil-ловушка:** интерфейс `== nil`, только если пусты тип и значение. С `nil`-указателем
  внутри он **не** `nil`. Возвращая `error` без ошибки, пиши литерал `nil`.
- `fmt.Stringer` (`String() string`): `fmt` проверяет его type switch'ем в рантайме.
  `error` проверяется раньше. С `any` ошибка получателя не ловится компилятором.

## Пакеты и видимость

- Заглавная буква — экспорт, строчная — нет. Граница — **пакет** (папка), не файл.
- `package main` + `func main()` — программа. Любое другое имя — библиотека.
- Импорт: `module` из `go.mod` + путь к папке. Имя пакета — как имя папки.
- Все файлы одной папки — один пакет.

## Стиль

- Ошибку проверяй сразу и выходи: `if err != nil { return ... }`, дальше без отступа.
- Короткие имена: `u`, `err`, `users`. Получатель — 1-2 буквы, одинаковый у всех методов.
- `Printf` → сразу `\n`. Для одного значения хватит `Println`.
- Мёртвый код удаляй, история есть в git.
- Перед показом кода: `go vet ./...`.
