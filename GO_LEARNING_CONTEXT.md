- `01-hello`: `package main` и `func main`, `fmt.Println`/`Printf`, глаголы `%s`/`%v`,
  запрет неиспользуемых переменных и импортов, `go run -work`
- `02-types`: `var` vs `:=`, zero values, `%T`, явные преобразования,
  `int(float)` отбрасывает дробную часть (truncation), строки в UTF-8 (`len` в байтах),
  `rune`, `range` по строке, `utf8.RuneCountInString`, затенение встроенного `len`

- `03-structs`: объявление `struct`, литерал с полями по имени и zero value через `var`,
  `%v` / `%+v` / `%#v` / `%q`, флаги форматирования (`-`, `0`, пробел, ширина — это printf
  из C, а не про структуры), blank identifier `_`, `rune` = `int32`
- Пакеты и видимость: заглавная буква = экспорт, граница — пакет (не файл, не тип),
  `export` как ключевого слова нет. Путь импорта = `module` из `go.mod` + путь к папке;
  центрального реестра нет, путь модуля это и есть адрес репозитория. Папка с `.go`
  файлами сама по себе пакет — никаких `index.ts`, баррелов и алиасов
- `encoding/json`: `Marshal` возвращает `[]byte` (нужен `string(...)` или `%s`),
  неэкспортируемые поля пропускает; `fmt` их через рефлексию всё же печатает
- **Передача по значению**: структура лежит в переменной целиком, а не по ссылке.
  Вызов функции и присваивание копируют все поля — оригинал не меняется.
  В JS объект это ссылка, в Go структура ведёт себя как примитив

- `04-pointers`: `&x` берёт адрес, `*p` разыменовывает. `*` в типе (`*int`) и как
  оператор — разные вещи. Указатель это обычное значение: его кладут в переменную,
  передают, возвращают — `birthday(p)` и `birthday(&age)` равнозначны.
  Передача по значению не нарушается: копируется адрес, но ведёт он туда же.
  Приоритет `.` выше `*`, поэтому `*u.Age` — ошибка, явная форма `(*u).Age`,
  а `u.Age` работает через синтаксический сахар.
  Zero value указателя — `nil`, разыменование даёт панику `nil pointer dereference`.
  `nil` полезен как «значения нет»: поиск не нашёл, поле не передали в PATCH
  (`Age *int` отличает «не передали» от «передали 0» — аналог `age?: number`).
  `int`, `string`, `bool`, struct не могут быть `nil` вообще.
  `new(T)` выделяет новую ячейку с zero value; `&x` берёт адрес существующей.
  На практике `new` редок — для структур пишут `&T{...}`

- `05-slice`: массив `[3]string` — размер часть типа, `[3]string` и `[4]string`
  несовместимы, размер обязан быть константой. Слайс `[]string` — это заголовок
  из трёх полей: `ptr` (адрес backing array), `len`, `cap`.
  `cap` — размер выделенного массива; растёт геометрически (до 256 элементов вдвое,
  дальше ~1.25x), но закон не зафиксирован и полагаться на него нельзя.
  `append` возвращает значение, потому что заголовок копируется и массив может переехать.
  **Копия всегда поверхностная**: `b := a` даёт свой заголовок, но общий массив —
  аналог `{...obj}` в JS. Структура без указателей копируется независимо.
  `append` разделяет слайсы только при `len == cap`; предсказать нельзя.
  Срез `e[0:2]` наследует `cap` до конца массива, и `append` молча затирает `e[2]`.
  Защита: `slices.Clone` (лучший), `make` + `copy` (копирует `min(len(dst), len(src))`,
  возвращает число скопированных), трёхиндексный срез `e[0:2:2]` обрезает `cap`.
  `nil`-слайс полностью рабочий: `len`/`cap` нули, `append` работает —
  `var s []int` это идиоматичный пустой слайс.
  Внутри функции `s[0] = 0` видно снаружи (общий `ptr`), а `append` нет (свой `len`);
  идиоматично возвращать слайс, а не брать `*[]int`.
- Ловушка `string(i)`: даёт символ с этим кодом, не текст цифры. Нужен
  `strconv.Itoa` или `fmt.Sprintf("%d")`. `go vet` это ловит — запускать привычно.

- `06-maps`: литерал и `make`, `delete`, `len`. Чтение отсутствующего ключа не падает —
  возвращает zero value; отличить «нет ключа» от «значение 0» через `v, ok := m[k]`
  (встроенный синтаксис, не функция — оборачивать не надо), часто внутри
  `if v, ok := m[k]; ok { ... }` — это `if` с инициализацией.
  `nil`-мапа: чтение и `len` работают, **запись роняет** (`assignment to entry in nil map`),
  потому что значение мапы это указатель на хеш-таблицу, а индексное присваивание
  ничего не возвращает и не может создать таблицу — в отличие от `append`, у которого
  есть канал возврата. Мапу всегда создавать через `make` или литерал.
  `range` по мапе даёт **намеренно случайный порядок**; нужен порядок — собрать ключи
  в слайс (`make([]string, 0, len(m))` + `append`) и `slices.Sort`.
  Мапа не сравнивается через `==` (только с `nil`) и не может быть ключом мапы —
  для сравнения `maps.Equal`, для копии `maps.Clone`.
  В функции мапа мутирует и видна снаружи (в переменной только `ptr`, своего
  состояния нет) — возвращать не нужно. Но `nil`-мапу внутри функции не починить.
- **Сводка копирования** (ключ ко всему этапу 1): копируется содержимое переменной,
  ровно и только оно. `int`/`string`/`struct` без указателей/массив — независимая копия;
  `*T` — общий объект; слайс — данные общие, `len` свой; мапа — всё общее (аналог
  `obj1 = obj2` в JS).

- `07-methods`: метод = функция с получателем `func (u *User) M()`, никакого `this`;
  получатель — обычный параметр (`user.User.Greet` — method expression, получатель
  становится первым аргументом). Методы объявляются только в пакете типа —
  `cannot define new methods on non-local type`, никакого prototype pollution.
  Value receiver работает с копией, pointer receiver меняет оригинал.
  Сахар при вызове: `u.M()` → `(&u).M()` и `p.M()` → `(*p).M()`, но только для
  **адресуемых** значений: переменная и элемент слайса — да; литерал, результат
  функции и элемент мапы — нет (`cannot call pointer method`). Исключение:
  `&T{...}` разрешён явно. Для мутации через мапу — `map[string]*User`;
  в литерале такой мапы можно опускать `&T`: `{"a": {Name: ...}}`.
  Сахар работает на переменных, **method set** — на типах: у `*T` все методы,
  у `T` только value-методы — выстрелит на интерфейсах.
  Соглашения: мутация или большая структура — pointer receiver; не смешивать
  типы получателей у одного типа (иначе value-метод молча мутирует копию).
  Доменные типы `type Age int`: новый тип, методы можно; `Age(20) + 5` работает
  (нетипизированная константа), `var x int = Age(20)` — нет, только `int(a)`.
  Аналог branded types в TS, но встроенный. `type Age = int` — псевдоним, не тип.

- `08-interfaces`: интерфейс — набор методов, `implements` нет. Соответствие
  проверяется в месте использования, сигнатура должна совпадать полностью.
  Интерфейс объявляют у потребителя; тип может подходить под интерфейс, о котором
  автор не знал. Проверка у объявления: `var _ Greeter = User{}`. В интерфейсе
  только методы (поведение, не данные); геттер называют `Name()`, не `GetName()`.
  Method set: методы на `*T` → в интерфейс годится только `*T`, сахара `&` нет,
  иначе метод менял бы копию внутри интерфейса.
  Интерфейсное значение — коробка (тип, значение). `%T` печатает динамический тип.
  Type assertion `g.(*User)` паникует при несовпадении, `v, ok := g.(*User)` — нет.
  Это не преобразование, а проверка. Type switch `switch v := g.(type)`: в ветке
  с одним типом `v` этого типа, в `default` и `case A, B:` — исходный интерфейс.
  Срабатывает первый подходящий `case` — конкретные типы выше интерфейсов.
  `any` = `interface{}`, подходит всё; по поведению это `unknown` из TS.
  **nil-ловушка**: интерфейс == nil только если пусты оба слота; с `nil`-указателем
  внутри он не nil. Метод можно вызвать на `nil`-получателе, падает разыменование.
  Через интерфейс доступны только его методы (статический тип).
  `fmt.Stringer` (`String() string`): `fmt` делает type switch в `handleMethods`,
  `error` проверяется раньше `Stringer`, только для `%v %s %x %X %q`. С `any`
  ошибка получателя не ловится компилятором — `String()` объявлять на value receiver.
  Исходники stdlib: F12 в VS Code, `C:/Program Files/Go/src`.

- `09-errors`: в Go нет `try/catch`, ошибка — значение и часть сигнатуры `(T, error)`.
  `error` — интерфейс с `Error() string`. Проверять сразу после вызова, до использования
  результата: `if err != nil { return 0, err }`, при ошибке возвращать zero value.
  В цикле ранний выход — `continue`. Пропущенная ошибка в Go тихая, не как в TS.
  Текст ошибки со строчной буквы, без точки, с контекстом: `parse age %q: ...`.
  `fmt.Errorf("...: %w", err)` кладёт ошибку внутрь новой (`*fmt.wrapError`),
  `%v` превращает в текст и теряет её. `errors.Unwrap` достаёт один слой.
  Sentinel-ошибка: `var ErrX = errors.New(...)` (префикс `Err`), в stdlib — `io.EOF`.
  `==` сравнивает только внешнюю коробку; `errors.Is` проходит всю цепочку.
  Всегда `errors.Is`, а не `==`: не знаешь, обернул ли кто-то ошибку по пути.
  Свой тип ошибки — структура с полями + `Error()` на указателе (как `*strconv.NumError`).
  `errors.As(err, &target)` ищет по **типу** и записывает найденное в переменную
  (поэтому `&`); `errors.Is` ищет конкретное **значение**. Что случилось → `Is`,
  нужны данные из полей → `As`. Объявлять `var t *T`, не `var t = *T`.
  nil-ловушка: `var e *AgeError; return e` даёт ненулевой `error`. Не заводить
  переменную конкретного типа ошибки: `return &AgeError{...}` и литерал `nil`.
  `fmt` печатает такую ошибку как `<nil>` — печать не доказательство.
  `log.Fatalf` = печать + `os.Exit(1)`, `defer` не выполняются. Только в `main`:
  функции возвращают ошибку, решение о завершении принимает вызывающий.
